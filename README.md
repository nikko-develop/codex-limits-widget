# Codex Limits для macOS

Плавающий виджет на SwiftUI и индикатор в строке меню. macOS 13+, Apple Silicon или Intel. Это самостоятельное приложение; оно не добавляется в галерею WidgetKit.

- Остаток каждого окна лимитов в процентах и время его сброса.
- Длительность окон берётся из ответа Codex: приложение не предполагает, что это всегда 5 часов и неделя.
- В строке меню — минимальный остаток среди окон. `~` перед процентом означает устаревшие данные.
- Автообновление каждые 5 минут, обновление после пробуждения и кнопка ручного обновления.
- Перетаскивание, сохранение положения, скрытие виджета и режим поверх окон.
- При ошибке остаются последние данные с предупреждением; после даты сброса проценты автоматически не обнуляются.
- Отдельная вкладка «Статистика»: токены по чатам, ходам диалога, запросам и моделям.
- Графики расхода по дням/часам и моделям, разбивка на вход, кэш, текст ответа и рассуждения.
- Поиск по чату/проекту, фильтры периода и модели, отдельный просмотр фоновых агентов.

## Сборка и запуск

Нужны Command Line Tools со Swift 6+ (или Xcode 16+), Python 3 из Command Line Tools и установленный Codex CLI. Полный Xcode, платный Apple Developer Account и сторонние библиотеки не нужны.

Если Command Line Tools ещё не установлены:

```bash
xcode-select --install
```

В папке проекта:

```bash
./scripts/build.sh
open "dist/Codex Limits.app"
```

Приложение собирается для архитектуры текущего Mac с локальной ad-hoc подписью. Готовую сборку можно перенести в `~/Applications` или «Программы». Для распространения с Developer ID понадобятся собственная подпись и notarization.

Скрипт использует кэши внутри `.build`. На некоторых обновлённых Command Line Tools остаются несовместимые старые файлы интерфейсов. `scripts/swift.sh` обнаруживает эти конкретные случаи и использует локальный VFS overlay; системные файлы не меняются.

## Подключение

Приложение ищет `codex` в стандартных путях Homebrew, `PATH`, приложении Codex и установленных расширениях OpenAI для VS Code/Cursor. Если CLI не найден, нажмите шестерёнку и выберите исполняемый файл вручную. Найти его в терминале:

```bash
command -v codex
codex --version
codex login
```

Нужен вход через ChatGPT в том же Codex CLI. Лимиты подписки недоступны при входе только через API-ключ. Если терминал не видит CLI из расширения, используйте его полный путь. В настройках виджета видно найденный путь.

Поле `CODEX_HOME` позволяет выбрать профиль Codex. Пустое поле сохраняет окружение запуска CLI и его стандартное расположение настроек. Запущенное из Finder приложение может иметь другое окружение, чем терминал: для нестандартного профиля укажите абсолютный путь явно. После изменений нажмите «Сохранить и обновить».

Левый клик по индикатору открывает карточку, правый — меню с настройками и выходом. Перетаскивайте виджет за свободное место. Чтобы он оставался видимым над другими приложениями, включите «Поверх других окон».

Автозапуск: Системные настройки → Основные → Объекты входа → добавьте `Codex Limits.app`, предварительно поместив его в постоянную папку.

## Статистика по сессиям

Переключитесь на вкладку **«Статистика»**. Виджет плавно расширится; переключение обратно вернёт компактную карточку лимитов. В малом окне переключатель занимает ширину блока с одинаковыми отступами, при расширении перемещается в левую часть хедера. Если в macOS включено уменьшение движения, размер меняется сразу. Статистика также доступна из карточки в строке меню.

Выберите период («Сегодня», 7/30 дней или всё время), модель и источник («Все», «Чаты», «Агенты»). Поиск работает по названию чата, каталогу проекта и идентификатору. Список по умолчанию отсортирован по расходу; кнопка справа от заголовка переключает сортировку на новые сессии.

Вверху показывается расход **за выбранный период**. График «Сегодня» строится по часам, остальные — по дням в часовом поясе Mac. Нажмите или проведите по графику, чтобы увидеть число токенов в выбранном интервале. График моделей показывает пять наиболее затратных моделей, фильтр позволяет выбрать любую модель.

Выбор чата открывает его детализацию: модели, распределение токенов и ходы диалога. Раскройте ход, чтобы увидеть короткую подпись задачи и запросы с датами, моделью, входом и выходом. При фильтрации периода учитывается дата каждого запроса, а не дата создания чата.

История автоматически перечитывается раз в минуту, пока открыта вкладка. Кнопка обновления запускает чтение сразу. Неизменившиеся файлы повторно не разбираются. При ошибке последняя статистика остаётся видна с предупреждением.

### Что означают суммы

- **Всего** — сумма токенов запросов, записанных в локальной истории. Это не уникальный объём текста: один и тот же контекст может обрабатываться в нескольких запросах.
- **Вход** включает кэшированные входные токены. **Выход** включает токены рассуждений. Кэш и рассуждения не прибавляются к итогу второй раз.
- Если старая запись содержит только общий счётчик, недостающая детализация показывается как «Без детализации». Неизвестная модель остаётся «Неизвестна».
- Имена моделей берутся из записи расхода или контекста хода. Внутреннее перенаправление модели, которое не отражено в истории, виджету неизвестно.
- Фоновые агенты отмечаются отдельно. Их записи не означают отдельное начисление в платёжном счёте.
- Токены **не переводятся в деньги или проценты лимита подписки**: история не содержит надёжного соответствия для такого расчёта.

Это статистика **локально сохранённой истории**, а не биллинг всего аккаунта. Удалённые, несохранённые и не синхронизированные с этим Mac чаты в неё не входят. Если один `CODEX_HOME` использовался несколькими аккаунтами, история может содержать их общие данные. Выберите нужную папку `CODEX_HOME` в настройках и сохраните изменения.

### Чтение истории

Вкладка читает `sessions/**/*.jsonl`, `archived_sessions/**/*.jsonl` и названия из `session_index.jsonl` в `CODEX_HOME` (по умолчанию `~/.codex`). Авторизация и сеть для этой вкладки не нужны.

Поддерживаются записи `token_usage_record` и старые события `token_count`. Для одного хода предпочтение отдаётся новым записям; старые накопительные счётчики пересчитываются в приращения. Повторные response ID, повторные счётчики и копии архивных файлов не увеличивают итог. Восстановленные из старого формата данные отмечаются в детализации. Эти внутренние форматы могут изменяться с версиями Codex.

Незавершённая последняя строка активного файла откладывается до следующего чтения. Ошибки чтения файлов и повреждённые строки отображаются как «Пропуски»; итог в этом случае может быть неполным.

История открывается только для чтения. В памяти остаются счётчики, имена моделей, названия чатов и подписи задач длиной до 300 символов. Ответы ассистента, команды и результаты инструментов не включаются в статистику. Статистика не сохраняется на диск и не отправляется на сервер.

## Источник данных

Используется документированный протокол [OpenAI Codex App Server](https://learn.chatgpt.com/docs/app-server):

1. Локальный дочерний процесс `codex app-server --listen stdio://`.
2. Запрос `initialize`, ожидание ответа, уведомление `initialized`.
3. Запрос `account/rateLimits/read`.

Запросы к моделям, создание чатов и расходование reset-кредитов не выполняются. CLI использует собственную авторизацию и сеть. Виджет не читает токены авторизации и не передаёт их в свой код; сырые диагностические сообщения сервера не сохраняются. Если в настройках CLI используется вход через Keychain, доступ обрабатывается самим CLI.

Показывается корзина `codex`; отдельные модельные корзины не подменяют её. Это лимиты аккаунта, выбранного в CLI, который может отличаться от аккаунта другого установленного приложения Codex. Отсутствующие данные не считаются 100% остатка.

Приложение сохраняет только проценты, окна, тариф и время получения в `~/Library/Caches/local.codex-limits-widget/limits.json`. Настройки и положение окна — в стандартных настройках macOS для `local.codex-limits-widget`.

## Проверка

```bash
./scripts/swift.sh test
"dist/Codex Limits.app/Contents/MacOS/CodexLimitsWidget" --check
"dist/Codex Limits.app/Contents/MacOS/CodexLimitsWidget" --check-usage
open "dist/Codex Limits.app" --args --demo
open "dist/Codex Limits.app" --args --demo --statistics
```

`--check` читает реальные лимиты и печатает только проценты и время сброса. Он использует автоматический поиск CLI и окружение терминала, а не пути из настроек GUI. `--demo` открывает интерфейс с явно помеченными тестовыми данными, не обращаясь к Codex.

`--check-usage` проверяет локальную историю и печатает только итоговые счётчики и модели, без названий/содержимого чатов. Он учитывает `CODEX_HOME` из окружения терминала. `--statistics` открывает приложение сразу на вкладке статистики; вместе с `--demo` позволяет посмотреть все графики без чтения истории.

Тесты проверяют разбор ответов, совместимость со старой формой ответа, выбор корзины, устаревание данных, JSON-RPC handshake, фрагменты сообщений, RPC-ошибки и тайм-аут. Транспортные тесты запускают временный локальный mock CLI; сеть и реальный аккаунт не нужны.

Для статистики проверяются оба формата истории, исключение дублей, сброс/наследование счётчиков, атрибуция моделей, архивные копии, фильтры, часовой пояс, фоновые агенты, частично записанные строки и обновление кэша. Тесты используют временные JSONL-файлы.

В среде, которая запрещает вложенную песочницу SwiftPM, используйте `./scripts/swift.sh test --disable-sandbox` или `./scripts/build.sh --disable-sandbox`. Этот флаг относится к выполнению manifest SwiftPM.
