# Codex Limits для macOS

Плавающий виджет на SwiftUI и индикатор в строке меню. macOS 13+, Apple Silicon или Intel. Это самостоятельное приложение; оно не добавляется в галерею WidgetKit.

- Остаток каждого окна лимитов в процентах и время его сброса.
- Длительность окон берётся из ответа Codex: приложение не предполагает, что это всегда 5 часов и неделя.
- В строке меню — минимальный остаток среди окон. `~` перед процентом означает устаревшие данные.
- Автообновление каждые 5 минут, обновление после пробуждения и кнопка ручного обновления.
- Перетаскивание, сохранение положения, скрытие виджета и режим поверх окон.
- При ошибке остаются последние данные с предупреждением; после даты сброса проценты автоматически не обнуляются.

## Сборка и запуск

Нужны Command Line Tools со Swift 6+ (или Xcode 16+), Python 3 из Command Line Tools и установленный Codex CLI. Полный Xcode, платный Apple Developer Account и сторонние библиотеки не нужны.

Если Command Line Tools ещё не установлены:

```bash
xcode-select --install
```

В папке проекта:

```bash
./scripts/build.sh
open "dist/Codex Limits.app"
```

Приложение собирается для архитектуры текущего Mac с локальной ad-hoc подписью. Готовую сборку можно перенести в `~/Applications` или «Программы». Для распространения с Developer ID понадобятся собственная подпись и notarization.

Скрипт использует кэши внутри `.build`. На некоторых обновлённых Command Line Tools остаются несовместимые старые файлы интерфейсов. `scripts/swift.sh` обнаруживает эти конкретные случаи и использует локальный VFS overlay; системные файлы не меняются.

## Подключение

Приложение ищет `codex` в стандартных путях Homebrew, `PATH`, приложении Codex и установленных расширениях OpenAI для VS Code/Cursor. Если CLI не найден, нажмите шестерёнку и выберите исполняемый файл вручную. Найти его в терминале:

```bash
command -v codex
codex --version
codex login
```

Нужен вход через ChatGPT в том же Codex CLI. Лимиты подписки недоступны при входе только через API-ключ. Если терминал не видит CLI из расширения, используйте его полный путь. В настройках виджета видно найденный путь.

Поле `CODEX_HOME` позволяет выбрать профиль Codex. Пустое поле сохраняет окружение запуска CLI и его стандартное расположение настроек. Запущенное из Finder приложение может иметь другое окружение, чем терминал: для нестандартного профиля укажите абсолютный путь явно. После изменений нажмите «Сохранить и обновить».

Левый клик по индикатору открывает карточку, правый — меню с настройками и выходом. Перетаскивайте виджет за свободное место. Чтобы он оставался видимым над другими приложениями, включите «Поверх других окон».

Автозапуск: Системные настройки → Основные → Объекты входа → добавьте `Codex Limits.app`, предварительно поместив его в постоянную папку.

## Источник данных

Используется документированный протокол [OpenAI Codex App Server](https://learn.chatgpt.com/docs/app-server):

1. Локальный дочерний процесс `codex app-server --listen stdio://`.
2. Запрос `initialize`, ожидание ответа, уведомление `initialized`.
3. Запрос `account/rateLimits/read`.

Запросы к моделям, создание чатов и расходование reset-кредитов не выполняются. CLI использует собственную авторизацию и сеть. Виджет не читает токены и не передаёт их в свой код; сырые диагностические сообщения сервера не сохраняются. Если в настройках CLI используется вход через Keychain, доступ обрабатывается самим CLI.

Показывается корзина `codex`; отдельные модельные корзины не подменяют её. Это лимиты аккаунта, выбранного в CLI, который может отличаться от аккаунта другого установленного приложения Codex. Отсутствующие данные не считаются 100% остатка.

Приложение сохраняет только проценты, окна, тариф и время получения в `~/Library/Caches/local.codex-limits-widget/limits.json`. Настройки и положение окна — в стандартных настройках macOS для `local.codex-limits-widget`.

## Проверка

```bash
./scripts/swift.sh test
"dist/Codex Limits.app/Contents/MacOS/CodexLimitsWidget" --check
open "dist/Codex Limits.app" --args --demo
```

`--check` читает реальные лимиты и печатает только проценты и время сброса. Он использует автоматический поиск CLI и окружение терминала, а не пути из настроек GUI. `--demo` открывает интерфейс с явно помеченными тестовыми данными, не обращаясь к Codex.

Тесты проверяют разбор ответов, совместимость со старой формой ответа, выбор корзины, устаревание данных, JSON-RPC handshake, фрагменты сообщений, RPC-ошибки и тайм-аут. Транспортные тесты запускают временный локальный mock CLI; сеть и реальный аккаунт не нужны.

В среде, которая запрещает вложенную песочницу SwiftPM, используйте `./scripts/swift.sh test --disable-sandbox` или `./scripts/build.sh --disable-sandbox`. Этот флаг относится к выполнению manifest SwiftPM.

## Как запушить в свой Git

Для **нового пустого репозитория** создайте его в GitHub/GitLab без README и замените адрес ниже на свой:

```bash
cd /Users/nikko/Projects/nikko/codex-limits-widget
git init -b main
git add .
git commit -m "Add macOS Codex limits widget"
git remote add origin git@github.com:YOUR_USERNAME/codex-limits-widget.git
git push -u origin main
```

Для GitLab или HTTPS используйте URL своего репозитория вместо примера. `.build` и `dist` исключены из Git: отправляются исходники и скрипты.

Если репозиторий **уже содержит код**, сначала клонируйте его в другую папку, скопируйте туда содержимое этого проекта без `.build`, `.swiftpm` и `dist`, затем выполните обычные `git add`, `git commit`, `git push`. Привязывать новую локальную историю к непустому репозиторию через force-push не требуется.

Git-репозиторий, коммиты и отправка на сервер автоматически не создаются.
